# Migration Targets

Date: 2026-04-13

## Goal
Define the first content targets DayOf should care about when someone is moving from another wedding platform.

## Core import targets

### 1. Story / welcome copy
Target fields:
- couple welcome note
- short story/about copy
- headline/subheadline-level intro text

Why it matters:
- this is the fastest way to keep the site from feeling empty after a move
- users should not have to rewrite their basic story from scratch

### 2. Event details
Target fields:
- wedding date
- venue name
- city / location
- ceremony / reception / extra event names and times when available

Why it matters:
- this is the structural backbone of the site and guest flow
- if these move cleanly, the rest of setup feels easier

### 3. FAQs
Target fields:
- question/answer pairs
- parking/travel/attire notes that can become FAQs

Why it matters:
- FAQs hold a lot of the operational guest guidance people already wrote elsewhere

### 4. Registry links
Target fields:
- external registry URLs
- simple registry labels/source names when available

Why it matters:
- registry links are common migration pain because couples do not want to re-enter them manually

## Secondary targets (later)
- gallery/photos
- accommodations/hotel blocks
- dress code sections
- contact/contact-person sections
- seating assignments (if migration source even supports them)

## Current recommendation
Migration work should prioritize:
1. event details
2. guest list
3. story/welcome copy
4. FAQs
5. registry links

That order gives the best first-draft recovery without pretending every source platform exports everything cleanly.
