# Use-case Pack Audit

Date: 2026-04-12

## Scope
Audit the first three use-case packs surfaced in product/discovery/setup:
- destination
- bilingual
- interfaith

## Current truth

### Destination
Status: stronger / materially real

Evidence:
- template discovery explicitly surfaces destination pack language
- setup direction explicitly supports destination mode
- onboarding + generation add destination-aware FAQ/travel defaults
- layout generation keeps travel sections alive more intentionally for destination use cases

Conclusion:
Destination is the only pack that currently feels materially deeper than a label.

### Bilingual
Status: partial / not deep enough yet

Evidence:
- setup and discovery mention bilingual
- generated FAQ copy can include bilingual guidance
- welcome-note drafting can shift tone slightly

Missing depth:
- no stronger structural template behavior yet
- no bilingual-specific section logic yet
- not enough visible proof in discovery compared with destination

Conclusion:
Bilingual currently exists more as guidance/default copy than as a truly differentiated pack.

### Interfaith
Status: partial / not deep enough yet

Evidence:
- setup and discovery mention interfaith
- generated FAQ copy can include ceremony context
- generation can add a ceremony-note schedule item

Missing depth:
- no stronger interfaith-specific section behavior yet
- no deeper ceremony/family guidance structure yet
- not enough visible proof in discovery compared with destination

Conclusion:
Interfaith currently exists more as guidance/default copy than as a truly differentiated pack.

## Overall call
- Destination = materially real enough to talk about with confidence
- Bilingual = partial
- Interfaith = partial

## Recommendation
Before claiming these three as equally mature packs, deepen bilingual and interfaith so they affect structure and discovery more visibly, not just copy.
