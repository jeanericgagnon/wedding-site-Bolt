# Multilingual polish audit

Date: 2026-04-13

## Current multilingual strengths
- i18n exists
- LanguageSwitcher exists
- SiteView and RSVP already use translation plumbing
- default site language exists in settings
- bilingual pack/content guidance exists

## Current weakness
The system still feels more like:
- language infrastructure + partial content support
than
- a fully productized multilingual wedding platform

## What would actually improve it
Not a giant translation system.
Just:
1. make language-switch behavior feel consistent
2. make default-language behavior more obvious/reliable
3. reduce places where English-only formatting leaks through awkwardly

## Honest conclusion
Multilingual support is already good enough for v1 if we do not oversell it.
It only needs small consistency polish, not a giant new project.

## Next step
- D2 decide whether to do one small language consistency pass or stop here
