# Custom styling depth audit

Date: 2026-04-13

## Current reality
The product already has real styling/customization depth through:
- template/theme system
- builder styling controls
- color / visual customization infrastructure
- section-level design variation system

## What is probably true
The gap is likely **not** that styling is absent.
The gap is more likely:
- no true freeform CSS editor
- maybe not enough exposed controls for power users
- roadmap wording may overstate how "fully custom" it needs to be

## Honest conclusion
For a wedding product, current styling depth is probably already **done enough for v1/core product**.
If we keep chasing this, we risk building a website-builder-for-builders instead of a wedding product.

## Best call
- do not open a big styling expansion batch right now
- treat section-1 styling as acceptable for v1
- keep true custom CSS as a later expansion, not a blocker

## Next step
- A3 multi-language truth audit, or end remaining-gap execution here
