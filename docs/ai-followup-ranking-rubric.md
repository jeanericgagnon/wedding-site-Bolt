# AI Follow-Up Ranking Rubric

Use this rubric to decide whether the system should ask another question after the initial intake.

## Hard rule
If the draft is already strong enough to ship a believable first version, do **not** ask follow-ups just because some fields are technically incomplete.

## Score each missing area by leverage
### 3 — high leverage
Ask if this meaningfully improves the guest-facing site or core operations.
- clarifies wedding anchor (date/place/venue certainty)
- clarifies event structure guests need to understand
- fixes a major guest-ops gap (RSVP, plus-ones, meals)
- unlocks multiple sections at once

### 2 — medium leverage
Ask if the site is otherwise good but could feel notably more complete.
- stronger story detail
- guest feel / emotional tone
- travel / lodging clarity when destination is relevant
- registry posture nuance

### 1 — low leverage
Usually do not interrupt for this unless there is no better question.
- purely decorative refinements
- tiny copy polish
- optional extras that don’t materially change the draft

## Stop conditions
Do not ask another follow-up if all of these are true:
- wedding anchor is usable
- event structure is usable
- guest ops are usable
- site tone can be drafted honestly
- remaining gaps are low- or medium-leverage only

## Bad follow-up patterns
Never ask:
- literal echoes of messy raw event strings
- hyper-narrow cleanup questions when a broader better question exists
- questions that only fill one tiny field when a more powerful question could fill several
- questions that restate info already clearly implied

## Better follow-up pattern
Prefer one question that can unlock multiple things at once.

Examples:
- "Walk me through the wedding weekend. What’s happening, and where are people actually going?"
- "What’s the version of your story that actually feels like you two?"
- "What do you want guests to feel most over the weekend?"
- "What should guests understand about the location or travel plan?"

## Ordering priority
1. wedding anchor / event clarity
2. guest operations
3. guest feel / site tone
4. story texture
5. registry nuance
6. optional polish
